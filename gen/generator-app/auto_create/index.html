JSON으로 RTL 생성

영도 스튜디오 설정 JSON을 전달하면 이 브라우저에서 프로젝트를 생성합니다. 별도 API 서버는 사용하지 않습니다.

에이전트용 프롬프트 / 사용 방법

JavaScript를 실행할 수 있는 브라우저로 이 페이지를 사용하세요. HTTP GET 응답 원문에는 생성 결과가 없습니다.

  1. 설정은 영도 스튜디오에서 내보낸 JSON과 같습니다. projectName, scheduler, decoder, formats, instructions를 사용하세요. 작성 전에 아래 JSON 필드 설명을 펼쳐 읽고 예제 JSON을 참고하세요.
  2. 주소에 ?config=encodeURIComponent(JSON.stringify(config))를 붙여 접속하세요. 실제로는 인코딩한 JSON 문자열을 넣습니다. 또는 #config=…로 전달해도 됩니다. URL이 너무 길면 #config-input에 JSON을 입력하고 #generate를 클릭하거나 JSON 파일을 선택하세요.
  3. #auto-create-status의 data-state가 ready 또는 error가 될 때까지 기다리세요. idle은 입력 대기, working은 생성 중입니다. 최대 30초를 기다리고 시간 초과를 성공으로 처리하지 마세요.
  4. error이면 #generation-error의 textContent를 읽으세요. ready이면 #generated-manifest의 textContent를 JSON으로 해석하세요.
  5. ZIP이 필요하면 다운로드 이벤트를 기다리도록 준비한 뒤 #download-zip을 클릭하고 archiveName으로 저장하세요.
  6. 개별 파일은 manifest의 files[].url을 브라우저로 여세요. ready를 기다린 뒤 #generated-file의 textContent를 UTF-8로 저장하세요. innerHTML이나 화면에 보이는 줄바꿈을 복사하지 마세요. 저장 경로는 files[].path이며 directories의 빈 폴더도 생성하세요.
  7. 파일 주소는 auto_create/file/?file=인코딩한파일경로#config=인코딩한JSON입니다. 파일 경로를 임의로 추측하지 말고 manifest에 나온 주소를 사용하세요. 존재하지 않는 파일은 error가 됩니다.

LSQ와 오륙도는 추후 제공입니다. 현재 영도 스튜디오와 동일한 을숙도 Gen2 생성기를 사용합니다. 합성이나 시뮬레이션은 실행하지 않습니다.

JSON 필드 설명 · 의미 / 타입 / 필수 여부 / 기본값

필수 항목은 JSON에 직접 넣어야 합니다. 아래의 예는 권장 시작값이며 생략 시 자동 적용되는 값이 아닙니다. 선택 항목만 생략할 수 있습니다. 자동값을 원하면 키를 생략하세요. null, 빈 문자열, "auto"로 대신하지 마세요. 수치는 JSON 숫자로, 참·거짓은 true/false로 작성합니다.

scheduler · 구조 파라미터

필드타입 / 필요의미와 값
platform문자열 / 선택생략 또는 "eulsukdo". "oryukdo"는 현재 생성 불가.
predictorMode문자열 / 선택생략 또는 "static". "external"은 현재 생성 불가.
decoderSource문자열 / 선택기본 "generated": 입력 레인별 디코더 생성·연결. "external": 디코더 파일을 제외하고 i_nel_decode_* 입력을 노출. 외부 모드에서도 decoder의 폭 설정은 필요합니다.
decodeWidth정수 / 필수사이클당 새 명령 입력 폭. 예 2. STRUCT_DECODE_NEW_INST.
phyRegs정수 / 필수물리 레지스터 개수. 예 64. decoder.instRegs와 decodeWidth 이상. STRUCT_PHYREGS.
robEntries정수 / 필수이름은 기존 JSON과의 호환용이며 실제로는 IST 엔트리 수. 예 128. 2 이상이며 decodeWidth 이상. STRUCT_INST_STATE_ENTRIES.
rsFifoEntries정수 / 선택EX 경로별 RS FIFO 최소 엔트리 수. 생략 시 128, IST 크기와 독립. 행 반올림과 버퍼 때문에 실제 저장량은 더 클 수 있습니다. STRUCT_RS_FIFO_WIDTH.
istIssueWidth정수 / 선택사이클당 IST → RS 명령 발행 폭. 생략하면 coresList[].count의 합. STRUCT_IST_ISSUE_WIDTH.
istBanks정수 / 선택IST 명령 저장 SRAM 뱅크 수. 생략하면 max(decodeWidth, istIssueWidth) 이상의 최소 2의 거듭제곱. 직접 지정할 때도 2의 거듭제곱이며 decodeWidth 이상이어야 합니다. STRUCT_IST_BANKS.
coresList객체 배열 / 필수EX 경로 목록. 최소 2개 경로, 각 경로에 실행 유닛 1개 이상. 배열 순서가 RTL의 EX 경로 번호(0부터)를 결정합니다. 아래 하위 필드 참조.
prmUpdate정수 / 필수사이클당 PRM → IST 준비 완료 통지 최대 개수. 명령 발행 폭과 별개. 예 5. STRUCT_PRM_ENTRY_UPDATE.
prmBuffer정수 / 필수PHYREG 하나당 대기 등록 슬롯 수. 초과 입력 버퍼 깊이가 아닙니다. 예 4. STRUCT_PRM_ENTRY_BUFFER.
unallocatePhyreg정수 / 필수사이클당 FCL → PRM 물리 레지스터 반환 폭. 예 4. STRUCT_UNALLOCATE_PHYREG.
flowWindows정수 / 필수FCL이 추적하는 Flow 윈도 개수. 2 이상, 예 8. STRUCT_FLOW_WINDOWS.
flowPcMaxRange정수 / 선택윈도당 최대 명령 수. 바이트 수가 아닙니다. 생략 시 16. STRUCT_FLOW_PC_MAX_RANGE.
enableMemoryOrder불리언 / 선택생략 또는 false. true는 미제공 LSQ를 요청하므로 오류.
memoryCoreId문자열 / 선택스튜디오가 메모리 경로로 표시할 coresList[].id. 생략한 JSON을 스튜디오에 불러오면 이름이 Memory인 경로를 찾습니다. 현재 이 값으로 LSQ나 실행 유닛을 생성하지 않으며, 명령의 실제 경로는 exPathId로 정합니다.

구조 개수와 폭은 모두 1 이상의 안전한 정수입니다(위에 2 이상으로 표시한 항목 제외). scheduler에 ISA 필드가 중복되어 있더라도 생성 시 decoder의 같은 필드가 우선합니다. ISA 필드는 아래 decoder에 작성하세요.

scheduler.coresList[] · 실행 경로

필드타입 / 필요의미와 값
id문자열 / 필수경로 참조용 ID. 예 "alu". 경로마다 고유하게 지정하고 명령의 exPathId에 같은 문자열을 사용합니다. 숫자처럼 보이더라도 문자열입니다.
name문자열 / 필수표시·주석용 경로 이름. 예 "ALU", "Memory". 이름만으로 연산 회로가 구현되지는 않습니다.
count정수 / 필수이 경로의 실행 유닛 수이자 RS 출력 레인 수. 1 이상. 목록 전체의 합이 STRUCT_EX_CORES, 각 값이 STRUCT_RS_OUT_ENTRY 배열에 들어갑니다.
stroke문자열 / 필수구조도 표시 색상. 예 "#48b4d5". RTL 동작에는 영향이 없지만 JSON 형식상 필요합니다.

예: Branch 1개 + ALU 3개 + Memory 1개는 3개 경로, 5개 실행 유닛입니다. 현재 생성기는 실행 유닛당 일반 완료 레인을 1개씩, 별도 분기 완료 레인을 1개 생성합니다. EX 연산 모듈 자체는 사용자가 연결합니다.

decoder · ISA 폭

필드타입 / 필요의미와 값
isaName문자열 / 필수생성 디코더의 모듈·파일 접두어. 예 "rv32i" → rv32i_decoder.sv. 영문자 또는 밑줄로 시작하고 영문자·숫자·밑줄만 사용합니다.
instBitWidth정수 / 필수명령어 비트 폭. 예 32. IS_INST_BITWIDTH.
instRegs정수 / 필수ISA 논리 레지스터 개수. 예 32. IS_INST_REGS. 레지스터 0은 zero register로 취급되는 구조입니다.
instOperands정수 / 필수소스 레지스터 피연산자 개수. 현재 2만 지원. 목적 레지스터는 여기에 포함하지 않습니다.
instImm정수 / 필수디코더가 출력할 확장된 즉시값 비트 폭. 예 32. IS_INST_IMM.
microopBitWidth정수 / 필수EX에 전달할 micro-op 코드 비트 폭. 예 5. EX_INST_MICROOP_BITWIDTH.

formats[] · 명령어 형식

필드타입 / 필요의미와 값
id문자열 / 필수형식 참조용 고유 ID. 예 "fmt-r". 명령의 formatId에서 참조.
name문자열 / 필수RTL 내부 신호 이름에 사용. 예 "R_type". 고유한 SystemVerilog 식별자로 작성하세요.
fields객체 배열 / 필수명령어 비트에서 추출할 필드 목록. 하위 필드는 다음 표 참조.
immediateParts객체 배열 / 선택분산된 즉시값 비트를 출력 즉시값의 지정 위치에 배치. 비어 있지 않으면 role: "imm"보다 우선합니다. 생략하거나 []이면 imm 역할 필드를 사용합니다.
signExtendImmediate불리언 / 선택immediateParts가 있을 때만 적용. 생략·false는 상위 빈 비트를 0으로 채움. true는 가장 높은 출력 구간의 소스 MSB로 상위를 부호 확장. 중간·하위 빈 비트는 항상 0입니다.

formats[].fields[] · 비트 필드

필드타입 / 필요의미와 값
id문자열 / 필수편집용 고유 ID. 예 "r-opcode". 판별 조건은 이 ID가 아닌 아래 name을 참조합니다.
name문자열 / 필수형식 안에서 고유한 SystemVerilog 식별자. 예 "opcode", "rd". conditions의 키와 일치해야 합니다.
msb정수 / 필수명령어에서 추출할 최상위 비트 번호(포함).
lsb정수 / 필수추출할 최하위 비트 번호(포함). 0 ≤ lsb ≤ msb < decoder.instBitWidth. 예 msb=6, lsb=0이면 7비트 opcode.
role문자열 / 필수"Condition": 명령 판별용, "rd": 목적 레지스터, "rs1"/"rs2": 소스 레지스터, "imm": 연속 즉시값, "None": 자동 출력 역할 없음. rd/rs1/rs2/imm은 형식마다 각각 하나만 지정하세요.

명령 판별에 사용할 필드는 conditions에도 직접 지정해야 합니다. role만 Condition으로 설정해도 비교 조건이 자동 추가되지는 않습니다. rd/rs 필드가 없으면 해당 출력은 0입니다. 레지스터 필드 폭은 ceil(log2(instRegs))에 맞추세요. immediateParts 없이 imm 필드만 쓰면 폭이 작을 때 항상 부호 확장하고, 폭이 클 때는 하위 instImm비트를 사용합니다. 두 방식 모두 없으면 즉시값은 0입니다.

formats[].immediateParts[] · 즉시값 조립

필드타입 / 필요의미와 값
id문자열 / 필수구간 편집용 고유 ID. 예 "b-imm-12".
sourceMsb정수 / 필수명령어에서 복사할 구간의 최상위 비트(포함).
sourceLsb정수 / 필수복사할 최하위 비트(포함). 0 ≤ sourceLsb ≤ sourceMsb < instBitWidth.
targetLsb정수 / 필수출력 즉시값에서 이 구간을 배치할 최하위 비트. 0 이상. 구간 끝이 instImm 미만이어야 하며 출력 구간끼리 겹치면 안 됩니다.

예: {"id":"b-imm-4-1","sourceMsb":11,"sourceLsb":8,"targetLsb":1}은 inst[11:8]을 imm[4:1]에 복사합니다. 어떤 구간도 imm[0]을 지정하지 않으면 해당 비트는 0입니다.

instructions[] · 명령 판별과 EX 전달

필드타입 / 필요의미와 값
id문자열 / 필수명령 편집용 고유 ID. 예 "inst-add".
name문자열 / 필수명령 이름이자 RTL decode 블록 이름의 일부. 예 "ADD". 고유한 SystemVerilog 식별자로 작성하세요.
formatId문자열 / 필수사용할 formats[].id. 반드시 실제 형식 ID를 참조해야 합니다.
conditions객체 / 필수필드 이름 → SystemVerilog 비교 상수 문자열. 예 {"opcode":"7'b0110011","funct3":"3'b000"}. 모든 비교를 AND로 묶습니다. 키는 선택한 형식의 fields[].name, 값의 폭은 해당 필드와 맞추세요. 빈 문자열 조건은 생략되며 {}는 무조건 일치하므로 주의하세요.
exPathId문자열 / 필수실행할 scheduler.coresList[].id. 배열 인덱스나 유닛 개수가 아닙니다. 실제 경로 ID를 사용하세요.
microop정수 / 필수EX 유닛에 전달할 연산 코드. 0 ≤ microop < 2^microopBitWidth로 작성하고 EX 구현의 코드와 맞추세요. 코드를 지정하는 것만으로 연산 회로가 생성되지는 않습니다.
newregAlloc불리언 / 필수목적 레지스터에 새 PHYREG 할당 요청. true여도 rd=0이면 생성 디코더가 요청을 끕니다.
jump불리언 / 필수점프 제어 출력 jump_o. JAL 예에서는 true.
jumpReg불리언 / 필수레지스터 기반 점프 제어 출력 jump_reg_o. 제공된 JALR 예에서는 jump=false, jumpReg=true, branch=false입니다.
branch불리언 / 필수조건 분기 제어 출력 branch_o. BEQ 등의 조건 분기에서 true. 일반 산술 명령은 jump/jumpReg/branch 모두 false.

명령 조건은 배열 앞에서부터 if / else if로 검사하므로 첫 일치 항목이 우선합니다. 아무것도 일치하지 않으면 illegal입니다. ID 연결·이름·비트 범위·micro-op 범위·조건 중복을 확인하세요. 현재 입력 검사가 모든 ISA 오류를 잡아주지는 않으며 ready는 파일 생성 완료를 뜻합니다.

출력 manifest · 생성 파일을 읽을 때

schemaVersion은 목록 형식 버전(현재 1), archiveName은 ZIP 이름, selectedFile은 현재 텍스트로 보여주는 파일 경로입니다. files[].path는 ZIP 안 저장 경로, files[].bytes는 UTF-8 바이트 수, files[].url은 같은 설정을 담은 개별 파일 페이지 주소입니다. directories는 빈 폴더 목록입니다. sourceVersion의 repository·commit·path·sha256은 동봉한 원본 RTL의 출처·커밋·소스 폴더·파일별 해시입니다. 이 manifest는 설정 입력 JSON이 아닙니다.
